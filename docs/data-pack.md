# 数据包组织规范（dsh-CET6-learn）

> 这份文档只描述**目录与文件约定**，不包含任何题目、录音或词表内容。
> 真实的题库请放在**私有仓库**或本机资料目录里；公开仓库只放代码与本文档。

> **先分清两种数据**：随包分发的 `starter/` 是**原创示例题库**（不碰真题，可公开分发，见 `NOTICE.md` 第 3 节），
> 它不是本文说的「数据包」；本文讲的是使用者自备真题的目录约定。两者结构相同，所以同一套构建产物格式通吃。

## 1. 为什么数据不进公开仓库

CET-6 的试题、听力录音、答案与词汇释义的著作权归原权利人（考试主办机构、出版方）。
把真题 PDF、听力音频或成规模的答案/释义放进公开仓库，等于向公众提供复制件，
不属于「个人学习研究」的合理使用。因此：

- **公开仓库（本仓库）**：只放代码、文档、目录模板。
- **数据包**：放在私有仓库或本机目录，例如 `~/.dsh/dsh-cet6/data-pack/`；
  构建时用 `--src` 指过去，产物默认写到 `~/.dsh/dsh-cet6/data/`。
- 如果确实想把数据也放到 GitHub：请把仓库设为 **Private**，或另开一个私有数据仓，
  不要把数据推到公开仓库。

## 2. 数据包根目录（按题型分类）

构建脚本按**内容**识别 `04` / `05`（六级资料里词汇常排在音频后面，与四级相反，
所以不看编号）：目录里有 `*.csv` 且文件名含「词」即判为词汇目录，有音频文件即判为音频目录。

```
data-pack/
├─ 01 真题试卷/
│  └─ <考期>/<套>/<任意文件名>.docx         # 首选 .docx；也可以是同名 .pdf 或 .txt 纯文本卷
├─ 02 答案/
│  └─ <任意名>.csv 或 <任意名>.txt          # 答案总表（CSV）或按题号排列的答案 TXT
├─ 03 听力原文/
│  └─ <YYYY年M月第N套>_听力原文.txt          # 可选；缺了听力题只能靠听
├─ 04 听力音频/
│  └─ <YYYY年M月第N套>听力音频.mp3           # 可选；支持 .mp3/.m4a/.aac
├─ 05 词汇/
│  ├─ 六级核心词汇2500.csv
│  └─ 六级大纲词汇6500.csv
└─ audio-tracks.json                        # 可选：分段表（见第 5 节）
```

**整卷优先读 docx**：`word/document.xml` 直读，按段落还原，能保住空号与题号，也不会混进 PDF
的水印行；docx 段落太少（不足 30 段）时才退回同名 PDF 抽文本。

为什么按题型而不是按考期：一份答案 CSV 与一份词表要覆盖所有考期；
按题型放，新增考期只是往 `01` 里多一个文件夹，不用动其它目录。

## 3. 以后怎么加新内容

### 加一套新真题

1. 把整卷 docx（或 PDF）放进 `01 真题试卷/<考期>/<套>/`；
2. 在 `02 答案/` 里补这套的 55 个客观题答案（听力 1–25、选词 26–35、匹配 36–45、阅读 46–55）——
   CSV 总表或纯答案 TXT 都可以，TXT 按题号区间自动判题型；
3. 有听力原文就放 `03 听力原文/`，有录音就放 `04 听力音频/`（文件名带上考期与套号）；
4. 若这套的听力标了「本部分与第 N 套共用」，构建会按标注记 `listenFrom` 借用同考期录音，
   可跨考期借（实测 `2024-12-s3` 借 `2024-12-s2`）；
5. `npm run build:data -- --src <数据包路径>`，再 `npm run check:data` 确认 `problems` 为空。

### 加一份新录音

放进 `04 听力音频/`，文件名必须能解析出「YYYY年M月…第N套」。构建会：

- 用同名听力原文与各套选项做关键词比对，判断它属于哪一套；
- 没有原文时按文件名归属并标 `audioVerified: false`（界面会提示「录音按套号推定」）。

### 加一批新单词

当前构建只识别两个词表文件（文件名分别含 `2500`、`6500` 或 `6000`）。
想加**新的词表分册**（例如「考研核心词」「物流专业词」），需要先扩展构建脚本与界面，
约定如下（供后续实现）：

- 文件：`05 词汇/<名称>.csv`，列与现有词表一致（编号、单词、音标、考频、释义、词性、例句、例句中译）；
- 产物：`vocab-<slug>.json` + `index.json` 里多一个 deck；
- 界面：首页按 deck 动态生成卡片，进度仍按单词共享（同一个词在多个分册里只算一次）。

在扩展完成前，新增 CSV 会被构建忽略，不会报错。

### 加分段表（按篇跳转）

`audio-tracks.json` 只是「某份录音第 N 节从第几秒到第几秒」，可以放在：
`--tracks` 参数、`CET6_TRACKS` 环境变量、数据包根目录、`04 听力音频/` 或 `~/.dsh/dsh-cet6/`。
六级的录音只分三节（A 长对话 / B 篇章 / C 讲座），所以分段表按 3 段写，不按篇拆。
构建会用音频真实时长校验，任何一段越界就整份作废并写 warning。

## 4. 数据包清单（建议）

在数据包根目录放一份 `pack.json`，方便自己记录版本与来源（构建不依赖它）：

```json
{
  "name": "cet6-2023-2026",
  "updatedAt": "2026-11-07",
  "source": "自购真题册 / 听力音频",
  "periods": ["2023-06", "2023-12", "2024-06", "2024-12", "2025-06", "2025-12", "2026-06"],
  "note": "仅个人学习使用，不公开分发"
}
```

## 5. 私有仓库的推荐做法

```bash
# 数据包单独一个私有仓库（GitHub → New repository → Private）
git init
git add .
git commit -m "data: CET-6 2023-2026 pack"
git remote add origin git@github.com:mount9527/dsh-cet6-data.git
git push -u origin main
```

在每台机器上：

```bash
git clone <私有数据仓> ~/.dsh/dsh-cet6/data-pack
npm run build:data -- --src ~/.dsh/dsh-cet6/data-pack
```

升级插件（`npm update dsh-cet6`）不会影响 `~/.dsh/dsh-cet6/`，题库与音频都还在。

## 6. 校验

```bash
npm run check:data      # 真题题库
npm run check:starter   # 内置示例题库（无音频、kind=starter、词数自洽）
```

`check:data` 会检查：答案数量、选词字母是否在词库、长篇阅读答案是否指向存在的段落、选项数、
选项是否粘连了下一段说明、听力题数/音轨是否存在、`index.json` 的录音统计是否与卷宗一致。

`check:starter` 是发版护栏，拦这四类事故：音频混进 `starter/`、`index.json` 忘了标 `kind: "starter"`、
卷宗里写了 `listening.audio`、`index.json` 声明的词数与词表实际条数不一致。

## 7. 示例卷的字段约定（想自己加原创卷时）

`starter/papers/*.json` 与真题卷结构相同，只有一处差别：**听力不指向音频文件**。

```json
{
  "synth": true,
  "listening": {
    "synth": true,
    "track": "",
    "audio": "",
    "verified": true,
    "passages": [
      { "key": "A", "section": "A", "sectionLabel": "长对话", "from": 1,  "to": 8,  "text": "…", "questions": [] },
      { "key": "B", "section": "B", "sectionLabel": "篇章",   "from": 9,  "to": 15, "text": "…", "questions": [] },
      { "key": "C", "section": "C", "sectionLabel": "讲座",   "from": 16, "to": 25, "text": "…", "questions": [] }
    ]
  }
}
```

- 六级录音只有 **Section A/B/C 三个分界**，没有「Conversation One」「Passage Two」这类篇名，
  所以 `passages` 就是「节」（3 项），`key` 用 `A` / `B` / `C`，节内题号由 `from` / `to` 圈定。
  `sectionLabel` 缺省时前端按 `A→长对话 / B→篇章 / C→讲座` 兜底。
- `listening.synth: true` 时前端不渲染 `<audio>`，改用 `SpeechSynthesis` 逐句朗读 `passages[].text`，
  按节点击单读、读完即停；交卷前不显示原文按钮（原文就是朗读内容，先给等于给答案）。
- 没有 `start` / `end` 时间轴也能用；有真人录音时删掉 `synth`、填上 `audio` 与 `track` 即可走常规播放路径。
- `index.json` 里对应记 `"synth": true` 与 `audio.synth` 计数，首页与听力菜单会据此显示「语音合成」。

新增第二套原创卷时，`build/check-starter.mjs` 会自动把它纳入检查（无音频、有原文、答案齐全，
听力必须是 3 节）。
